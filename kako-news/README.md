# کاکو نیوز — سامانهٔ خبرخوان و انتشار خودکار

سامانه‌ای که به‌صورت دوره‌ای از چند منبع خبری، اخبار مرتبط با **شیراز** را جمع‌آوری
می‌کند، آن‌ها را با رعایت اصول نگارش خبری فارسی بازنویسی می‌کند، در یک **صف تأیید**
می‌گذارد تا سردبیر ببیند، و پس از تأیید در **سایت وردپرسی کاکو نیوز** و **کانال تلگرام**
منتشر می‌کند.

> وضعیت فعلی: **مایل‌استون ۴ — موتور بازنویسی خبری**
> مراحل بعدی در بخش [نقشهٔ راه](#نقشهٔ-راه) فهرست شده‌اند.

---

## مسیر یک خبر در سامانه

```
منابع خبری
    │
    ▼
[۱] جمع‌آوری (Collector)        →  جدول raw_articles
    │                              آداپتور RSS یا اسکرِیپر اختصاصی
    ▼
[۲] فیلتر مرتبط‌بودن با شیراز   →  خبرهای نامرتبط: وضعیت irrelevant (حذف نمی‌شوند)
    │
    ▼
[۳] تشخیص تکراری (Dedup)        →  منبع دوم به‌عنوان «منبع تکمیلی» لینک می‌شود
    │
    ▼
[۴] بازنویسی با هوش مصنوعی      →  جدول articles با وضعیت pending_review
    │                              (متن منبع هرگز عیناً کپی نمی‌شود)
    ▼
[۵] صف تأیید (پنل مدیریت)       →  سردبیر ویرایش/تأیید/رد می‌کند
    │
    ▼
[۶] انتشار                      →  وردپرس  +  کانال تلگرام  (جدول publications)
```

## استک فنی

| لایه | انتخاب |
|---|---|
| زبان و رانتایم | Node.js 22 + TypeScript (بدون مرحلهٔ build در توسعه) |
| دیتابیس | PostgreSQL 16 |
| سایت | **وردپرس** (سایت فعلی کاکو نیوز) — انتشار از راه REST API |
| پنل تأیید | سرویس وب سبک داخل همین پروژه |
| بازنویسی | OpenAI API (مدل از فایل کانفیگ قابل تغییر) |
| تلگرام | Telegram Bot API |

**چرا Next.js نساختیم؟** سایت کاکو نیوز وردپرسی است و صفحهٔ اصلی، دسته‌بندی،
صفحهٔ خبر و نشانی‌های سئوفرندلی فارسی را خودش دارد. ساختن یک فرانت‌اند دوم یعنی
نگهداری و سئوی موازی. پس ماژول انتشار، پست را مستقیم در وردپرس می‌سازد. اگر روزی
خواستید سایت را از وردپرس جدا کنید، همین سرویس یک API خواندنی هم می‌دهد که
هر فرانت‌اندی بتواند رویش سوار شود.

## نصب و راه‌اندازی

### گام ۱ — نصب وابستگی‌ها

```bash
cd kako-news
npm install
```

### گام ۲ — بالا آوردن دیتابیس

اگر PostgreSQL روی سیستم‌تان نصب است، یک دیتابیس بسازید:

```bash
createdb kako_news
```

یا با Docker (ساده‌تر):

```bash
docker compose up -d
```

### گام ۳ — ساخت فایل تنظیمات

```bash
cp .env.example .env
```

سپس `.env` را باز کنید و مقادیر را پر کنید:

| متغیر | توضیح | لازم از مایل‌استون |
|---|---|---|
| `DATABASE_URL` | نشانی اتصال به PostgreSQL | ۱ |
| `OPENAI_API_KEY` | کلید از [platform.openai.com](https://platform.openai.com/api-keys) | ۴ |
| `OPENAI_MODEL` | مدل بازنویسی، مثلاً `gpt-4o-mini` | ۴ |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | ورود به پنل تأیید | ۵ |
| `SESSION_SECRET` | کلید امضای کوکی نشست | ۵ |
| `WORDPRESS_URL` | نشانی سایت، مثلاً `https://kakonews.ir` | ۶ |
| `WORDPRESS_USERNAME` | نام کاربری وردپرس | ۶ |
| `WORDPRESS_APP_PASSWORD` | «رمز برنامه» وردپرس (نه رمز اصلی!) | ۶ |
| `TELEGRAM_BOT_TOKEN` | توکن ربات از [@BotFather](https://t.me/BotFather) | ۷ |
| `TELEGRAM_CHANNEL_ID` | شناسهٔ کانال، مثل `@kakonews` | ۷ |

برای ساخت مقدار تصادفی `SESSION_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> **فایل `.env` هرگز نباید در گیت کامیت شود.** در `.gitignore` قرار دارد.

#### ساخت «رمز برنامه» وردپرس

پیشخوان وردپرس ← **کاربران** ← پروفایل کاربر ← بخش **Application Passwords** ←
یک نام مثل `kako-bot` بدهید ← رمز تولیدشده را در `WORDPRESS_APP_PASSWORD` بگذارید.
این رمز فقط برای API است و با رمز ورود شما فرق دارد.

### گام ۴ — ساخت جدول‌های دیتابیس

```bash
npm run migrate
```

### گام ۵ — بررسی سلامت تنظیمات

```bash
npm run config:check   # اعتبارسنجی .env و config/app.yaml
npm run db:status      # وضعیت اتصال دیتابیس و مهاجرت‌ها
```

## افزودن منبع خبری جدید

منابع در فایل `config/sources.yaml` تعریف می‌شوند — **هیچ منبعی در کد نیست.**
راهنمای کامل هر گزینه با مثال، در `config/sources.example.yaml` آمده است.

### اگر منبع RSS دارد (حالت ترجیحی)

```yaml
  - slug: farsnews-shiraz          # شناسهٔ یکتا؛ فقط حروف کوچک انگلیسی و خط تیره
    name: "خبرگزاری فارس — فارس"
    type: rss
    url: "https://example.com/rss/fars"
    homepage: "https://example.com"
    enabled: true
    poll_interval_seconds: 900     # هر ۱۵ دقیقه
    fetch_full_content: true       # متن کامل را از صفحهٔ خود خبر بگیر
    article:
      body_selector: ".news-body"  # بدنهٔ متن در صفحهٔ خبر
      remove_selectors: [".related-news", ".ads"]
```

همیشه اگر سایت فید RSS دارد همین را انتخاب کنید: فید یک قرارداد پایدار است و
با عوض شدن قالب سایت خراب نمی‌شود.

### اگر منبع RSS ندارد

```yaml
  - slug: sitename-archive
    name: "نام سایت"
    type: scrape
    url: "https://example.com/archive/shiraz"   # صفحهٔ فهرست یا آرشیو
    enabled: true
    poll_interval_seconds: 1200
    list:                          # سلکتورهای صفحهٔ فهرست
      item_selector: "ul.news-list > li"
      title_selector: "h3 a"
      link_selector: "h3 a"
      summary_selector: "p.summary"
      date_selector: "time"
      date_attribute: "datetime"
    article:                       # سلکتورهای صفحهٔ اختصاصی خبر
      body_selector: "div.article-body"
      remove_selectors: [".related", ".tags"]
```

**پیدا کردن سلکتور:** صفحه را در مرورگر باز کنید ← روی عنوان خبر راست‌کلیک ←
Inspect ← روی المان راست‌کلیک ← Copy ← Copy selector. سلکتور را ساده کنید
(کلاس‌های تصادفی و شماره‌ها را بردارید). هرچه سلکتور ساده‌تر باشد، با تغییر
قالب سایت دیرتر خراب می‌شود.

### پس از هر ویرایش

```bash
npm run sources:sync                      # اعمال تغییرات فایل در دیتابیس
npm run collect -- --source=<slug> --force  # آزمایش همان منبع
npm run sources:list                      # دیدن وضعیت سلامت منابع
```

> منبعی که از فایل حذف کنید **پاک نمی‌شود**، فقط غیرفعال می‌شود — چون خبرهای
> جمع‌آوری‌شده‌اش به آن ارجاع دارند و تاریخچه نباید از بین برود.

## آزمایش بدون منبع واقعی

منبع `mock-local` داده‌اش را از `fixtures/mock-source.json` می‌خواند تا بتوانید
کل پایپ‌لاین را بدون اینترنت و بدون فشار آوردن به سایت‌های واقعی اجرا کنید:


دادهٔ نمونه عمداً ترکیبی است از چند خبر مرتبط با شیراز، یک خبر سراسری نامرتبط،
و یک خبر تکراری از زاویهٔ دیگر — تا در مایل‌استون‌های بعدی، فیلتر شیراز و
تشخیص تکراری روی دادهٔ واقع‌نما آزمایش شوند.

## فیلتر مرتبط‌بودن با شیراز

هر خبر خام پیش از بازنویسی باید ثابت کند که واقعاً خبر شیراز است. تصمیم در
دو لایه گرفته می‌شود تا هزینهٔ مدل زبانی فقط جایی خرج شود که لازم است:

```
امتیاز کلیدواژه‌ای ≥ ۴   → قطعاً مرتبط    (بدون تماس با مدل، رایگان)
امتیاز < ۱               → قطعاً نامرتبط  (بدون تماس با مدل، رایگان)
بین ۱ تا ۴               → از مدل زبانی پرسیده می‌شود
```

آستانه‌ها با آزمایش روی دادهٔ واقع‌نما تنظیم شده‌اند: خبر آشکارا شیرازی
معمولاً ۹ تا ۱۵ می‌گیرد، خبر سراسری منفی یا صفر.

### واژه‌نامه — `config/shiraz-keywords.yaml`

بیش از ۱۷۰ عبارت در گروه‌های وزن‌دار: نام شهر و استان، نهادهای شهری و
استانی، دانشگاه‌ها و بیمارستان‌ها، جاذبه‌ها و بناهای تاریخی، محله‌ها و
معابر، تیم‌های ورزشی، و شهرهای دیگر استان فارس (با وزن کمتر).

هرچه این فایل کامل‌تر باشد، فیلتر دقیق‌تر و تماس با مدل زبانی کمتر می‌شود.
**بدون نیاز به تغییر کد قابل ویرایش است.**

### تله‌هایی که فیلتر می‌شناسد

کلمهٔ «فارس» همیشه به استان فارس اشاره نمی‌کند. این عبارت‌ها پیش از
امتیازدهی از متن حذف می‌شوند:

| عبارت | چرا |
|---|---|
| خبرگزاری فارس | یک خبرگزاری سراسری است؛ بدون این، هر خبر فارس‌نیوز «محلی» شمرده می‌شد |
| خلیج فارس | جغرافیای ملی است، نه استان |
| زبان/ادبیات فارسی | ربطی به استان ندارد |

همچنین «فارسی» به‌اشتباه با «فارس» تطبیق نمی‌کند، ولی «شیرازی» و
«شیرازی‌ها» درست شناسایی می‌شوند.

### نشانه‌های منفی

نام شهرهای دیگر و نهادهای سراسری امتیاز را کم می‌کنند، اما **جریمه سقف
دارد** — تا خبری مثل «شهردار شیراز در تهران با وزیر کشور دیدار کرد»
به‌اشتباه کنار گذاشته نشود.

### وقتی مدل زبانی در دسترس نیست

اگر کلید OpenAI تنظیم نشده باشد یا تماس خطا بدهد، سیستم **متوقف نمی‌شود**:
تصمیم به معیار کلیدواژه‌ای برمی‌گردد و روش تصمیم `llm_failed` ثبت می‌شود تا
بعداً قابل بازبینی باشد.

### خبرهای نامرتبط پاک نمی‌شوند

با وضعیت `irrelevant` بایگانی می‌شوند، همراه با امتیاز، کلیدواژه‌های
پیداشده و دلیل تصمیم. این‌طور می‌توانید ببینید فیلتر کجا اشتباه کرده و
واژه‌نامه را بهتر کنید.

## تشخیص خبر تکراری

وقتی چند خبرگزاری یک رویداد را پوشش می‌دهند، کاکو نیوز نباید چند بار همان
خبر را منتشر کند. مشکل اینجاست که نگارش‌ها کاملاً متفاوت‌اند:

```
«بهره‌برداری از فاز نخست خط دو قطار شهری شیراز تا پایان سال»
«فاز اول خط ۲ مترو شیراز تا پایان سال افتتاح می‌شود»
```

هیچ هش یا تطبیق دقیقی این دو را یکی نمی‌بیند.

### روش سنجش

واژه‌های معنادار دو خبر با **ضریب هم‌پوشانی وزن‌دار** مقایسه می‌شوند:

- **چرا Jaccard نه:** Jaccard اختلاف طول را جریمه می‌کند؛ وقتی یک منبع خبر
  مفصل و دیگری خبر کوتاه می‌نویسد، امتیاز بی‌دلیل پایین می‌آید. ضریب
  هم‌پوشانی (تقسیم بر مجموعهٔ کوچک‌تر) دقیقاً برای همین حالت است.
- **عددها وزن دوبرابر دارند:** «۸۵ درصد» و «۴۰ هزار نفر» نشانهٔ قوی‌تری از
  هم‌رویداد بودن‌اند تا واژه‌های عمومی.
- امتیاز نهایی = نیمی از شباهت تیتر + نیمی از شباهت متن.

روی دادهٔ نمونه، جفت واقعاً تکراری **۰٫۶۵۵** گرفت و بیشترین امتیاز میان
خبرهای بی‌ربط **۰٫۱۴۴** بود — آستانهٔ ۰٫۴۵ در فاصلهٔ امنی میان این دو است.

### قدیمی‌ترین گزارش، خبر اصلی می‌شود

خبرها به ترتیب زمان انتشار پردازش می‌شوند و هر خبر فقط با خبرهایی مقایسه
می‌شود که **قبلاً از این مرحله رد شده‌اند**. نتیجه: همیشه اولین گزارش از یک
رویداد «خبر اصلی» است و بقیه به آن وصل می‌شوند؛ دو خبر هم‌زمان نمی‌توانند
یکدیگر را تکراری اعلام کنند.

### منبع دوم دور ریخته نمی‌شود

با `on_duplicate: "link"` در `app.yaml`، خبر تکراری به‌عنوان **منبع تکمیلی**
به خبر اصلی وصل می‌شود تا در بازنویسی بتوان از جزئیات هر دو استفاده کرد و
در پایان خبر همهٔ منابع ذکر شوند. اگر `ignore` بگذارید، فقط کنار گذاشته
می‌شود.

## موتور بازنویسی

خبر منبع هرگز عیناً منتشر نمی‌شود. مدل زبانی آن را از نو می‌نویسد تا به
خبری اصیل و متعلق به کاکو نیوز تبدیل شود.

### دو فایلی که سبک نگارش را تعیین می‌کنند

هر دو **بدون تغییر کد** قابل ویرایش‌اند و در بازنویسی بعدی اعمال می‌شوند:

| فایل | کار |
|---|---|
| `config/style-guide.md` | راهنمای سبک نگارشی: تیتر، لید، هرم وارونه، لحن، نگارش فارسی، قاعدهٔ «بازنویسی نه کپی» |
| `config/prompts/rewrite.system.md` | پرامپت سیستمی؛ راهنمای سبک و دسته‌بندی‌ها داخلش تزریق می‌شوند |

راهنمای سبک شامل نکته‌های عملی است: نیم‌فاصله، «ی» و «ک» فارسی، ارقام
فارسی، پرهیز از صفت‌های احساسی، فعل خنثی برای نقل قول، و اینکه هیچ عددی
حدس زده یا گرد نشود.

### خروجی ساختاریافته

مدل باید JSON با این ساختار برگرداند:

```json
{
  "title":    "تیتر خبری کوتاه",
  "lead":     "پاراگراف اول بر اساس هرم وارونه",
  "body":     "متن کامل با پاراگراف‌های جدا",
  "category": "یکی از دسته‌بندی‌های مجاز",
  "tags":     ["برچسب یک", "برچسب دو"]
}
```

### سه محافظ روی خروجی مدل

**۱. اعتبارسنجی و اصلاح ساختار** — مدل زبانی همیشه دقیقاً قالب خواسته‌شده
را نمی‌دهد. این‌ها خودکار اصلاح می‌شوند:

| مشکل | اصلاح |
|---|---|
| دسته‌بندی خارج از فهرست («شهری» به‌جای «شهری و عمرانی») | به نزدیک‌ترین دستهٔ مجاز نگاشت می‌شود |
| تکرار لید در ابتدای متن | پاراگراف تکراری حذف می‌شود |
| نوشتن خط «منبع: …» توسط مدل | حذف می‌شود؛ سامانه خودش می‌سازد |
| نشانه‌گذاری مارک‌داون در متن | پاک می‌شود |
| تگ تکراری، خالی، یا رشتهٔ جدا شده با ویرگول | مرتب و یکتا می‌شود |
| متن بیش از حد کوتاه | خبر رد می‌شود |

هر اصلاح در `rewrite_meta` ثبت می‌شود تا بشود کیفیت مدل را بازبینی کرد.

**۲. محافظ کپی عینی** — مهم‌ترین محافظ. مدل گاهی به‌جای بازنویسی، جمله‌های
منبع را با جابه‌جایی چند کلمه برمی‌گرداند. سامانه دنباله‌های ۸ کلمه‌ای متن
منبع را با متن بازنویسی‌شده مقایسه می‌کند:

| حالت | نسبت کپی | طولانی‌ترین دنبالهٔ مشترک |
|---|---|---|
| کپی کامل | ۱٫۰ | ۴۶ کلمه |
| تغییر چند کلمه (حالت خطرناک) | ۰٫۳۸۵ | ۱۷ کلمه |
| بازنویسی واقعی | ۰٫۰ | ۴ کلمه |

آستانه‌ها در `app.yaml`: `max_verbatim_ratio: 0.15` و `max_verbatim_run: 12`.

اگر خروجی رد شود، **یک بار دیگر با تذکر صریح‌تر** به مدل داده می‌شود. اگر
باز هم کپی بود، خبر با وضعیت `failed` کنار گذاشته می‌شود و **هرگز به صف
تأیید نمی‌رسد**.

> نقل قول مستقیم داخل گیومه از این سنجش کنار گذاشته می‌شود — حرف کسی را
> نباید عوض کرد.

**۳. ثبت هزینه** — تعداد توکن، مدت زمان و شمارهٔ تلاش هر تماس در
`rewrite_meta` ذخیره می‌شود.

### منابع تکمیلی

اگر خبری در مرحلهٔ تشخیص تکراری، «منبع تکمیلی» گرفته باشد، متن آن منابع هم
به مدل داده می‌شود تا جزئیاتی که فقط در آن‌ها آمده از دست نرود. خط پایانی
خبر هم نام همهٔ منابع را می‌آورد.

### خط «منبع: …» را سامانه می‌سازد، نه مدل

مدل صریحاً منع شده که این خط را بنویسد. سامانه آن را از روی **منابع واقعی
ثبت‌شده در دیتابیس** می‌سازد. دلیلش: نام منبع همیشه دقیق است، منابع تکمیلی
هم ذکر می‌شوند، و مدل نمی‌تواند نام منبعی را از خودش بسازد. قالبش در
`app.yaml` قابل تغییر است.

### نشانی سئوفرندلی فارسی

از تیتر، اسلاگ فارسی ساخته می‌شود:

```
«خط دو قطار شهری شیراز تا پایان سال به بهره‌برداری می‌رسد»
  ↓
/خط-دو-قطار-شهری-شیراز-تا-پایان-سال-به-بهره-برداری-می-رسد
```

اگر اسلاگ تکراری باشد پسوند عددی می‌گیرد تا نشانی خبر قدیمی نشکند.

### هیچ خبری خودکار منتشر نمی‌شود

خبر بازنویسی‌شده **همیشه** با وضعیت `pending_review` ثبت می‌شود. در کد هیچ
مسیری وجود ندارد که خبری را بدون عبور از صف تأیید منتشر کند.

```bash
npm run rewrite    # بازنویسی خبرهای آماده
npm run queue      # دیدن صف تأیید
```

## چرخهٔ کامل وضعیت یک خبر

```
                       ┌─────────────┐
   جمع‌آوری  ─────────▶ │     new     │
                       └──────┬──────┘
                              │  فیلتر شیراز
                    ┌─────────┴─────────┐
                    ▼                   ▼
            ┌──────────────┐     ┌─────────────┐
            │  irrelevant  │     │  new (امتیاز‌دار) │
            │  (بایگانی)   │     └──────┬──────┘
            └──────────────┘            │  تشخیص تکراری
                              ┌─────────┴─────────┐
                              ▼                   ▼
                      ┌──────────────┐     ┌─────────────┐
                      │  duplicate   │     │    ready    │
                      │ (منبع تکمیلی)│     │ آمادهٔ بازنویسی│
                      └──────┬───────┘     └──────┬──────┘
                             │  بازنویسی          │
                             └────────┬───────────┘
                                      ▼
                            ┌───────────────────┐
                            │  articles         │
                            │  pending_review   │  ← منتظر تصمیم سردبیر
                            └───────────────────┘
```

هر گذار در جدول `pipeline_events` ثبت می‌شود، پس همیشه می‌توان دید یک خبر
دقیقاً کجا و چرا کنار گذاشته شده است.

## رفتار سیستم هنگام خطای منبع

| اتفاق | واکنش سیستم |
|---|---|
| سایت منبع پایین است | خطا در `sources.last_error` ثبت، منبع skip، **بقیهٔ منابع ادامه** |
| قالب سایت عوض شده (سلکتور بی‌نتیجه) | خطای گویا: «احتمالاً قالب سایت منبع تغییر کرده است» |
| صفحهٔ یک خبر باز نشد | همان خبر با اطلاعات فهرست ذخیره می‌شود، بقیه ادامه |
| یک آیتم فهرست ناقص است | فقط هشدار؛ آیتم رد می‌شود |
| پاسخ ۵۰۰ یا ۴۲۹ | تلاش مجدد با فاصلهٔ فزاینده (۱، ۲، ۴ ثانیه) |

شمار شکست‌های پیاپی هر منبع در `sources.consecutive_failures` نگه‌داری می‌شود
تا در پنل مدیریت منابع مشکل‌دار قابل تشخیص باشند.

## جدول‌های دیتابیس

| جدول | کار |
|---|---|
| `sources` | منابع خبری (آینهٔ `config/sources.yaml` + وضعیت اجرایی هر منبع) |
| `raw_articles` | خبر خام پیش از هر پردازشی، همراه با هش محتوا برای تشخیص تکراری |
| `articles` | خبر بازنویسی‌شدهٔ کاکو نیوز با وضعیت صف تأیید |
| `article_sources` | پیوند خبر به منبع اصلی و منابع تکمیلی |
| `publications` | نتیجهٔ انتشار در هر مقصد (سایت / تلگرام) |
| `job_runs` | تاریخچهٔ اجرای کارهای دوره‌ای |
| `pipeline_events` | ردپای هر خبر در تمام مراحل، برای دیباگ |
| `admin_users` | کاربران پنل تأیید (رمز با scrypt هش می‌شود) |

### وضعیت‌های خبر

**`raw_articles.status`**
`new` → تازه جمع‌آوری شده · `irrelevant` → مرتبط با شیراز نبود ·
`duplicate` → تکراری بود · `ready` → آمادهٔ بازنویسی ·
`processing` → در حال بازنویسی · `processed` → بازنویسی شد · `failed` → خطا خورد

**`articles.status`**
`pending_review` → منتظر تأیید سردبیر · `approved` → تأیید شد ·
`publishing` → در حال ارسال · `published` → منتشر شد ·
`rejected` → رد شد · `failed` → انتشار خطا خورد

## اصول ثابت پروژه

1. **هیچ کلیدی در کد نیست.** همهٔ کلیدها و رمزها از `.env` می‌آیند.
2. **هیچ چیزی هاردکد نیست.** منابع خبری، دسته‌بندی‌ها، آستانه‌ها و راهنمای
   نگارشی همه در فایل‌های `config/` قابل ویرایش‌اند.
3. **متن منبع هرگز عیناً کپی نمی‌شود.** هم به دلیل حق نشر، هم برای اصالت محتوای
   کاکو نیوز.
4. **هیچ خبری خودکار منتشر نمی‌شود.** هر خبر پیش از انتشار از صف تأیید رد می‌شود.
5. **خطای یک منبع، بقیه را زمین نمی‌زند.** منبع خطادار skip و لاگ می‌شود.
6. **هیچ داده‌ای پاک نمی‌شود.** خبرهای نامرتبط یا تکراری فقط وضعیت‌شان عوض
   می‌شود تا بعداً بتوان دلیل تصمیم را بررسی کرد.
