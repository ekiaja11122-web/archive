# نرم‌افزار مدیریت آرشیو صوتی و تصویری

نرم‌افزاری برای فهرست‌برداری و مدیریت آرشیو سخنرانی‌ها و فایل‌های صوتی و تصویری
که روی **هاردهای مختلف** پراکنده‌اند.

> **فایل‌های صوتی و تصویری وارد نرم‌افزار نمی‌شوند.**
> تنها *اطلاعات* آن‌ها ثبت می‌شود: هر فایل کجاست، روی کدام هارد، برای کیست،
> چه زمانی ضبط شده، چه نواقصی دارد و چه کسی آن را ثبت کرده است.
> فایل‌های اصلی سر جای خودشان روی هاردها باقی می‌مانند.

---

## راه‌اندازی (یک‌بار برای همیشه)

### گام ۱ — نصب Node.js
اگر روی رایانه‌تان نصب نیست، نسخهٔ **LTS** را از [nodejs.org](https://nodejs.org) دانلود و نصب کنید.
(نسخهٔ ۲۲ یا بالاتر لازم است.)

### گام ۲ — اجرای برنامه

| سیستم عامل | کاری که باید بکنید |
|---|---|
| ویندوز | روی فایل **«شروع برنامه (ویندوز).bat»** دوبار کلیک کنید |
| مک / لینوکس | روی فایل **«شروع برنامه (مک و لینوکس).command»** دوبار کلیک کنید |
| از خط فرمان | دستور `npm start` را اجرا کنید |

مرورگر به‌صورت خودکار باز می‌شود. اگر باز نشد، این نشانی را در مرورگر بزنید:
**http://localhost:7788**

> هیچ نصب اضافه‌ای لازم نیست — نرم‌افزار **هیچ وابستگی خارجی ندارد**
> و نیازی به اجرای `npm install` نیست.

پنجرهٔ سیاه (خط فرمان) را تا زمانی که با برنامه کار می‌کنید نبندید.
برای بستن برنامه در آن پنجره `Ctrl + C` بزنید.

## آشنایی با ساختار

نرم‌افزار روی سه مفهوم ساده بنا شده است:

```
هارد  ←  نسخه  ←  رکورد
```

| مفهوم | یعنی چه |
|---|---|
| **رکورد** | یک محتوا؛ مثلاً «تفسیر سورهٔ بقره — جلسهٔ ۳». عنوان، تاریخ، موضوع و نواقص روی رکورد ثبت می‌شود. |
| **نسخه** | یک فایل واقعی روی یک هارد مشخص، با مسیر و نام فایل. |
| **هارد** | حافظه‌ای که فایل‌ها روی آن هستند؛ هارد اکسترنال، SSD، فلش، DVD یا فضای ابری. |

نکتهٔ مهم: **یک رکورد می‌تواند چند نسخه داشته باشد.**
اگر همان سخنرانی روی سه هارد کپی شده، یک رکورد می‌سازید و سه نسخه به آن اضافه می‌کنید.
این‌طور نرم‌افزار می‌تواند به شما بگوید کدام محتوا نسخهٔ پشتیبان ندارد.

## شمارهٔ هاردها

هر هارد به‌صورت خودکار شماره‌ای یکتا می‌گیرد: `HD-001`، `HD-002` و…
هر رکورد هم کدی مانند `AR-00001` می‌گیرد.

پیشوند و تعداد ارقام این کدها در **تنظیمات ← عمومی** قابل تغییر است.

در صفحهٔ **هاردها** دکمه‌ای هست به نام **«چاپ برچسب هاردها»**؛
با آن می‌توانید برچسب‌های کاغذی چاپ کنید و روی هاردهای فیزیکی بچسبانید
تا شمارهٔ هر هارد از روی خودش پیدا باشد.

## آنچه برای هر رکورد می‌توانید ثبت کنید

**شناسایی:** عنوان، عنوان فرعی، کد آرشیو، نوع رسانه (صوتی/تصویری/تصویر/سند)

**نسبت‌دادن:** سخنران یا گوینده، دسته‌بندی درختی، مجموعه و شمارهٔ جلسه، برچسب‌ها

**زمان و مکان:** تاریخ ایراد به **هجری شمسی**، دقت تاریخ (روز/ماه/سال/نامشخص)،
تاریخ قمری، محل ایراد، شهر، مناسبت، مدت زمان

**کیفیت و نواقص:** کیفیت، کامل بودن محتوا، ۱۶ نوع نقص آماده
(نویز، ابتدای قطع‌شده، صدای کم، ناهماهنگی صدا و تصویر و…)، شرح نواقص، نشان «نیازمند رسیدگی»

**سوابق ثبت:** تاریخ ثبت (شمسی)، نام ثبت‌کننده، منبع تهیه، تحویل‌دهنده،
وضعیت تأیید، وضعیت انتشار، امتیاز، اولویت

**محل نگهداری:** برای هر نسخه — هارد، مسیر پوشه، نام فایل، قالب، حجم،
کیفیت تصویر، نقش نسخه (اصلی/پشتیبان/تبدیل‌شده)، سلامت فایل، تاریخ آخرین بررسی

## افزودن گروهی — ثبت یک مجموعهٔ کامل

برای اینکه مجبور نباشید ۴۰ جلسهٔ یک تفسیر را یکی‌یکی وارد کنید،
دکمهٔ **«⊞ افزودن گروهی»** در داشبورد و صفحهٔ آرشیو یک مجموعه را یکجا ثبت می‌کند.

پنجره سه بخش دارد:

### ۱ — فهرست از کجا ساخته شود؟

| روش | چه زمانی مناسب است |
|---|---|
| **📁 پویش پوشهٔ هارد** | فایل‌ها روی هارد هستند و هارد وصل است — بهترین حالت |
| **📋 چسباندن فهرست** | فهرست نام‌ها را از جایی کپی کرده‌اید |
| **🔢 تولید خودکار جلسات** | مثلاً «جلسهٔ ۱ تا ۴۰» بدون آنکه فایلی در دست باشد |

در روش **پویش پوشه** مسیر پوشه را می‌دهید (در ویندوز: پوشه را باز کنید،
روی نوار نشانی بالای پنجره کلیک کنید، مسیر را کپی کرده و بچسبانید) و نرم‌افزار خودش:

- همهٔ فایل‌های صوتی و تصویری داخل پوشه را پیدا می‌کند (در صورت تمایل، زیرپوشه‌ها را هم)
- نام، حجم و قالب هر فایل را می‌خواند
- **شمارهٔ جلسه را از نام فایل حدس می‌زند** — «۰۳-تفسیر بقره.mp3» می‌شود جلسهٔ ۳
  (سال‌هایی مانند ۱۳۹۸ و کیفیت‌هایی مانند 1080p را اشتباهاً شمارهٔ جلسه نمی‌گیرد)
- نام مجموعه و مسیر پوشه را خودکار پر می‌کند

> اگر ابزار **ffmpeg** روی رایانه نصب باشد، می‌توانید تیک «مدت زمان فایل‌ها هم خوانده شود»
> را بزنید تا مدت هر فایل هم خودکار خوانده شود. نصب ffmpeg اختیاری است.

**اگر پوشه‌ای را دوباره پویش کنید**، فایل‌هایی که پیش‌تر ثبت شده‌اند نشان
«ثبت شده» می‌گیرند و تیکشان برداشته می‌شود، تا رکورد تکراری ساخته نشود.

### ۲ — اطلاعات مشترک

اطلاعاتی که برای همهٔ جلسات یکسان است را **یک‌بار** پر می‌کنید و روی همهٔ ردیف‌ها می‌نشیند:
سخنران، دسته‌بندی، نام مجموعه، هارد، مسیر پوشه، مناسبت، محل ایراد، شهر، موضوع،
کیفیت، منبع تهیه، تحویل‌دهنده، ثبت‌کننده و برچسب‌ها.

**الگوی عنوان** تعیین می‌کند عنوان هر رکورد چطور ساخته شود:

| الگو | نتیجه |
|---|---|
| `{مجموعه} — جلسهٔ {شماره}` | تفسیر سورهٔ بقره — جلسهٔ ۷ |
| `{مجموعه} ({شماره})` | تفسیر سورهٔ بقره (۷) |
| `{نام فایل}` | همان نام فایل بدون پسوند |

با تغییر الگو، عنوان همهٔ ردیف‌ها بی‌درنگ به‌روز می‌شود.

### ۳ — پیش‌نمایش و ویرایش

جدولی از ردیف‌ها می‌بینید و پیش از ثبت می‌توانید:

- ردیف‌های ناخواسته را از تیک بیندازید یا حذف کنید
- شمارهٔ جلسه، عنوان، مدت زمان و تاریخ ایراد هر ردیف را جداگانه اصلاح کنید
- با کادر **«تاریخ ایراد یکسان»** یک تاریخ را روی همهٔ ردیف‌های انتخاب‌شده بگذارید

در پایان دکمهٔ **«ثبت … رکورد»** همه را یکجا ثبت می‌کند.
ثبت به‌صورت «همه یا هیچ» انجام می‌شود؛ اگر ردیفی مشکل داشته باشد، هیچ رکوردی ساخته نمی‌شود.

> پویش پوشه فقط از روی همین رایانه کار می‌کند. اگر برنامه را روی شبکه باز کرده باشید
> (`HOST=0.0.0.0`)، این بخش برای رایانه‌های دیگر بسته است.

## جست‌وجو

کادر جست‌وجوی بالای صفحه **همهٔ اطلاعات** را می‌گردد:
عنوان، موضوع، خلاصه، توضیحات، نام فایل، مسیر پوشه، نام و شمارهٔ هارد،
برچسب، سخنران، دسته‌بندی، مناسبت و محل.

جست‌وجو به شکل نگارش حساس نیست:

| اگر بنویسید | پیدا می‌کند |
|---|---|
| `ایت الله` | آیت‌الله ، آيت‌الله ، آیت الله |
| `نهج البلاغه` | نهج‌البلاغه (با نیم‌فاصله) |
| `جلسه ۱۲` | جلسه 12 |
| `محمد` | مُحَمَّد (با اعراب) |

**جست‌وجوی پیشرفته:**

| نوشتار | معنی |
|---|---|
| `نماز شب` | هر دو واژه باید باشند |
| `"شب قدر"` | دقیقاً همین عبارت |
| `رمضان -تکراری` | «رمضان» باشد ولی «تکراری» نباشد |

علاوه بر این، **پالایهٔ پیشرفته** در صفحهٔ آرشیو امکان محدود کردن نتایج را
بر پایهٔ نوع رسانه، دسته، هارد، سخنران، برچسب، مجموعه، مناسبت، کیفیت،
سال و بازهٔ تاریخ، و وضعیت (تأییدشده، دارای نقص، بدون پشتیبان و…) می‌دهد.

نتیجهٔ هر جست‌وجو در نشانی صفحه ذخیره می‌شود، پس می‌توانید آن را
نشانک (بوکمارک) کنید یا برای همکارتان بفرستید.

## گزارش‌های سلامت آرشیو

صفحهٔ **گزارش‌ها** کاستی‌های آرشیو را پیدا می‌کند:

| گزارش | چه چیزی را نشان می‌دهد |
|---|---|
| رکوردهای بدون فایل | رکوردهایی که هیچ نسخه‌ای روی هیچ هاردی ندارند |
| بدون نسخهٔ پشتیبان | فقط روی یک هارد هستند — در خطر از دست رفتن |
| فایل‌های خراب یا مفقود | نسخه‌هایی که خراب یا ناموجود گزارش شده‌اند |
| دارای نقص محتوایی | رکوردهایی که نیاز به بازسازی دارند |
| بررسی‌نشده‌ها | هنوز کسی صحتشان را تأیید نکرده |
| بدون تاریخ | تاریخ ایرادشان ثبت نشده |
| موارد احتمالاً تکراری | عنوان یکسان، شمارهٔ جلسهٔ تکراری، یا فایل با اثر انگشت یکسان |
| هاردهای نیازمند بازبینی | تاریخ بررسی دوره‌ای‌شان رسیده است |

## پشتیبان‌گیری و بردن آرشیو به رایانهٔ دیگر

همهٔ اطلاعات در یک فایل روی همین رایانه نگهداری می‌شود: `data/archive.db`

**نرم‌افزار هر ۲۴ ساعت یک پشتیبان خودکار** در پوشهٔ `backups/` می‌سازد
(۳۰ پشتیبان آخر نگه داشته می‌شود).

### بردن آرشیو به رایانهٔ دوم

سه گام:

1. **یک پشتیبان کامل بگیرید** — از **تنظیمات ← خروجی و ورودی ← دانلود پشتیبان کامل**،
   یا از خط فرمان: `npm run backup`
2. **نرم‌افزار را روی رایانهٔ دوم راه بیندازید** — پوشهٔ برنامه را کپی کنید،
   Node.js را نصب کنید و یک‌بار اجرا کنید
3. **پشتیبان را بازیابی کنید** — در **تنظیمات ← خروجی و ورودی ← بازیابی از فایل پشتیبان**،
   یا از خط فرمان: `npm run backup -- --restore "مسیر فایل"`

فایل پشتیبان یک فایل JSON مستقل است و **همهٔ** اطلاعات آرشیو
(رکوردها، هاردها، نسخه‌ها، دسته‌بندی‌ها، اشخاص، برچسب‌ها و تنظیمات) را در خود دارد.

### دستورهای خط فرمان

```bash
npm run backup                            # ساخت پشتیبان در پوشهٔ backups
npm run backup -- --out "E:\Flash"        # ساخت پشتیبان روی فلش یا هارد
npm run backup -- --list                  # فهرست پشتیبان‌های موجود
npm run backup -- --verify "فایل.json"    # بررسی سالم بودن یک فایل پشتیبان
npm run backup -- --restore "فایل.json"   # بازیابی از یک فایل پشتیبان
```

این دستورها بدون باز بودن نرم‌افزار هم کار می‌کنند.

### محافظت‌هایی که در کار است

- **بررسی پیش از بازیابی:** هر فایل پشتیبان اثر انگشتی (checksum) دارد.
  اگر فایل ناقص یا خراب باشد، پیش از پاک شدن اطلاعات فعلی جلوی بازیابی گرفته می‌شود.
- **پشتیبان ایمنی:** درست پیش از بازیابی، خودکار یک پشتیبان از وضعیت فعلی
  با نام `پیش-از-بازیابی-…` ساخته می‌شود. اگر اشتباهی رخ داد، راه برگشت دارید.

### اگر ترجیح می‌دهید کل پوشه را کپی کنید

می‌توانید به‌جای فایل پشتیبان، کل پوشهٔ برنامه (به‌ویژه `data/`) را کپی کنید.
**اما حتماً اول برنامه را ببندید.** تا وقتی برنامه باز است، بخشی از آخرین تغییرها
ممکن است هنوز در فایل کمکی `archive.db-wal` باشد و روی `archive.db` ننشسته باشد؛
با بستن برنامه همه‌چیز روی فایل اصلی نوشته می‌شود.

فایل پشتیبان JSON این مشکل را ندارد و همیشه کامل است — برای انتقال، همان مطمئن‌تر است.

> **توصیه:** هر چند وقت یک‌بار فایل پشتیبان را روی فلش یا یکی از همان هاردهای
> آرشیو کپی کنید. پشتیبانی که کنار اصل نسخه روی همان رایانه بماند،
> در برابر خرابی دیسک بی‌فایده است.

در **تنظیمات ← خروجی و ورودی** می‌توانید فهرست رکوردها را
به شکل فایل **اکسل (CSV)** هم بگیرید (این فایل برای بازیابی به کار نمی‌آید).

## دادهٔ نمونه (اختیاری)

اگر می‌خواهید پیش از وارد کردن اطلاعات واقعی، با نرم‌افزار آشنا شوید:

```bash
npm run demo              # ساخت چند ده رکورد و هارد ساختگی
npm run demo -- --clear   # پاک کردن کامل دادهٔ نمونه
```

## نکات فنی

- **بدون وابستگی خارجی** — تنها از امکانات داخلی Node.js استفاده می‌کند
  (`node:sqlite` و `node:http`)، پس `npm install` لازم نیست و برنامه سال‌ها بعد هم اجرا می‌شود.
- **آفلاین** — هیچ ارتباطی با اینترنت برقرار نمی‌شود؛ اطلاعات شما جایی نمی‌رود.
- **فقط روی همین رایانه** — سرور تنها روی `127.0.0.1` گوش می‌دهد.
- تبدیل تاریخ شمسی ↔ میلادی به‌صورت دقیق انجام می‌شود
  و تاریخ‌ها برای مرتب‌سازی، معادل میلادی‌شان هم ذخیره می‌شود.

### اجرای برنامه روی درگاه دیگر

```bash
PORT=8080 npm start        # مک و لینوکس
set PORT=8080 && npm start # ویندوز
```

### در دسترس قرار دادن برای رایانه‌های دیگر شبکه

```bash
HOST=0.0.0.0 PORT=7788 npm start
```

> هشدار: در این حالت هر کسی در شبکهٔ محلی می‌تواند اطلاعات را ببیند و تغییر دهد.
> نرم‌افزار رمز ورود ندارد، پس این کار را فقط در شبکهٔ مورد اعتماد انجام دهید.
